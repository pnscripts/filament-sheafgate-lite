# Changelog

All notable changes to Sheafgate Lite are listed here. The project follows [Semantic Versioning](https://semver.org/).

## 1.0.0 - 2026-11-05

First release.

- `ImportAction`, a drop-in replacement for Filament 5's import action that reads XLSX, ODS and CSV/TSV files.
- Filament's column mapping, validation, queued chunks, notifications and failed-rows download work unchanged.
- CSV encodings detected: UTF-8 (with or without BOM), UTF-16 LE/BE, Windows-1251 and Windows-1252; delimiters: comma, semicolon, tab, vertical bar.
- Sheet choice for workbooks with several sheets; header row found below title rows; merged, blank and duplicate header cells named.
- Spreadsheet values read faithfully: dates (1900 and 1904 systems), times, booleans, formulas as their saved results, numbers without float noise, leading zeros in text cells kept.
- The mapping shows an example value next to each file column.
- Clear messages for old .xls files, damaged workbooks and empty sheets.
- Safety limits: 50 000 data rows (or `maxRows()`) and real unpacked size counted per workbook part (10 MB or 100x its packed size, 256 MB in total), 32,767 characters per cell, checked before and while reading.
- Caps on what a file can declare: 16,384 cells per row (CSV: fields per line), every row counted toward the row limit before it is trimmed to the header, cells right of the header never stored, at most 2 million shared strings, read lazily.
- Hardened after security review round 6: every archive part measured whatever its name, no padding to whitespace-only far cells, one row-element budget (2,097,152) and one cell-element budget (4,000,000) per request, empty rows and cells included, shared parts read once, at most 1,000 sheets, libxml's nesting limit kept (no `LIBXML_PARSEHUGE`), ODS space runs clamped, CSV blank lines counted and CSV cells capped at 32,767 characters.
- Hardened after security review round 7, with budgets on the work rather than patches per file: a header may span at most 1,024 columns and every row is kept, padded and stored at the header's real width only (a header as wide as a sheet is refused, and rows from repeat attributes or with values past the budget are never taken for the header); repeated ODS cells and rows count as often as they are expanded; at most 128 MB of data per import and 4 MB per row; no cell is built as a DOM, every XML node (text, whitespace, comments and processing instructions included) counts against one budget per request that grows with the values read (4 million nodes plus 24 per value, 32 million at most), at most 4,096 nodes per cell and 10,000 comments or processing instructions per file, counted before parsing; no stretch of an XML part longer than 512 KB without a tag; cell text gathered in steps and refused past 131,068 bytes; number format codes over 255 characters ignored; shared text up to 32 MB. All 59 hostile files of review rounds 5 to 7 are refused or read within 5 s under a 128 MB `memory_limit` (at most 73 MB resident memory), and the whole test suite runs at 128 MB.
- Hardened after security review round 8: only UTF-8 parts are read (a UTF-16/UTF-32 byte order mark, NUL bytes, a first character other than `<` or another declared encoding is refused before parsing) and no part may hold a document type declaration; nodes allowed at 12 per value, 32 per shared string item and 1 per two empty cell elements next to real values (48 million at most); empty cell elements count half toward a cell budget of 6 million; a time budget of 10 s plus 8 µs per value per request; the 128 MB import budget counts the stored JSON. All 97 files of review rounds 5 to 8 are refused or read within 16 s with at most 87 MB resident memory under a 128 MB `memory_limit`, and the 40,000-row comparison with openpyxl still shows 0 differences.
- XLSX and ODS are read in a separate PHP process after review round 9 (never in the web request or queue worker): it caps its own memory (`memory_limit` 128 MB, address space 512 MB via `RLIMIT_AS`) and CPU time, hands rows back as JSON lines in batches the request asks for, and is killed past a wall clock of 20 s plus 8 µs per value it returned (`config` key `reader`: `timeout`, `memory_mb`, `address_space_mb`, `php_binary`). This bounds what libxml does inside one call (a start tag with 70,000 attributes took 35 s to over 7 minutes of CPU before). Where `proc_open` is disabled or no PHP command-line binary is found, XLSX and ODS are refused with a clear message and CSV still works. All 141 files of review rounds 5 to 9 are refused or read within 20.3 s under a 128 MB `memory_limit` with no reader process left behind (the nine attribute floods of round 9 are stopped at the wall clock after 20.1 to 20.3 s), and the 40,000-row comparison with openpyxl still shows 0 differences.
- CSV read by a parser of its own in 64 KB steps: a lone CR is a line break like LF and CRLF (inside quotes it stays in the value), UTF-32 files with a byte order mark are decoded, NUL bytes are refused, and the delimiter is detected from the first 64 KB.
- Excel's 1900 date system: serials 1 to 59 (1900-01-01 to 1900-02-28) read as Excel shows them.
- Formulas without a saved result and error cells (`#DIV/0!`) refuse the file with the cell named, never import 0 or empty.
- English and Bulgarian translations.
